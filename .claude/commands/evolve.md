# 自进化流程

分析过去日报的表现，优化系统配置，实现自我改进。

## 执行步骤

### 第一步：收集数据
读取以下文件获取分析基础：
- `data/state.json` — 管道历史、错误记录、已有学习
- `data/sources.json` — 信息源配置和性能数据
- `docs/_posts/` — 最近 7-14 天的日报文章

列出 `docs/_posts/` 下最近的 14 个文件，读取其中最新的 7 个完整内容。

### 第二步：分析信息源表现
对每个活跃信息源，计算以下指标：
1. **贡献度**：该源提供的文章占总文章数的比例
2. **独特性**：该源独有（其他源未覆盖）的文章数
3. **质量趋势**：近 7 天平均 rating 的变化趋势
4. **活跃度**：最近是否有产出（连续 3 天无产出标记为"枯竭"）

从 `sources.json` 的 `performance` 字段和历史文章分布提取数据。

### 第三步：分析分类健康度
统计最近 7 天各分类的文章数量和占比：
- 识别"过度倾斜"分类（占比 > 30%）
- 识别"稀疏"分类（占比 < 5%，连续多天缺失）
- 建议需要加强的信息源方向

### 第四步：分析文章质量
抽样最近文章的质量指标：
- 摘要长度是否在 80-150 字范围
- 标题是否有足够的多样性
- 是否存在重复或高度相似的标题
- 评分分布是否合理（避免全 3 星）

### 第五步：生成改进方案
基于以上分析，生成具体的改进方案：

**信息源调整**（更新 `data/sources.json`）：
- 给持续优质的信息源增加权重（+1, 上限 10）
- 给枯竭或低质量的信息源降低权重（-1, 下限 1）
- 如果某信息源连续 7 天无产出，标记为 inactive
- 如果有新的信息源建议，添加到 sources 列表
- 更新 performance 数据

**搜索策略优化**（更新 `data/sources.json` 中的 search_queries）：
- 为稀疏分类增加针对性的搜索词
- 替换效果不佳的搜索词
- 添加时效性更强的搜索词变体

**提示词优化**（更新 `data/state.json` 的 learnings）：
- 记录什么样的文章摘要效果好
- 记录需要避免的摘要模式
- 更新分类分配的经验规则

### 第六步：写入进化记录
更新 `data/state.json`：
- evolution.last_run 设置为当前时间
- evolution.total_runs +1
- evolution.current_generation +1
- evolution.run_history 追加本次进化记录
- learnings 更新改进发现

### 第七步：发送进化摘要邮件
```bash
uv run python scripts/send_email.py notify \
  --subject "Jarvis 自进化报告 Gen-{generation}" \
  --body "<html><body>本次进化摘要的 HTML 内容</body></html>" \
  --html
```

邮件内容包含：
- 当前代数
- 信息源调整（哪些升/降了权重）
- 分类健康度概况
- 关键改进发现
- 下次进化建议关注点

### 第八步：提交并推送
```bash
git add data/ docs/_posts/ && git commit -m "Evolution: gen-{generation} - {简短描述}" && git push
```

## 进化指导原则
- **保守进化**：每次调整幅度不超过 ±2 权重
- **数据驱动**：基于实际数据做判断，不凭空猜测
- **可逆性**：每次进化单独记录，便于回溯
- **多样性优先**：避免所有信息源趋同，保持来源多样性
- **中文优先**：优先中文源和中文内容，确保日报的可读性
